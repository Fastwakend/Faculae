# 编译与设备验收

本机已在 Windows 的 WSL2 中执行 61 个核心测试并全部通过。iOS 编译状态见 `local-validation.json`；以下真机界面与真实 API 测试仍需执行。

## 编译与核心测试

在 Xcode 26+ 的 Mac 中运行：

```bash
bash scripts/verify_macos.sh
```

预期：61 个 `SeekCore` XCTest 用例通过，随后 Xcode 完成 iOS Simulator Debug 编译。此脚本失败时应先修复错误，再进行设备验收。直接运行 `swift test --package-path Packages/SeekCore` 可单独检查协议层。

Windows 本地构建与签名安装步骤见 [BUILD-WINDOWS-WSL.md](BUILD-WINDOWS-WSL.md)。在 PowerShell 中运行 `wsl.exe -d Ubuntu-24.04 -- bash '/mnt/d/codex projects/ai前端/scripts/build_wsl.sh'`，可依次执行测试并生成未签名 IPA。

## 三种协议的联网测试

每种协议分别保存服务配置和对应的 Key，再读取模型列表或手动指定已获权限的模型。每次都开启一条新对话，发送“请只回复：连接成功”，然后追问“刚才我让你回复了什么”，检查多轮上下文。

| 配置 | 需验证 |
| --- | --- |
| OpenAI 兼容 | 原生 OpenAI 或兼容中转，使用 Chat Completions 路由，流式文字出现 |
| DeepSeek | 使用公开 API 地址，普通模型与深度思考模型均可调用，思考内容单独展示 |
| Gemini | 选择 Gemini 协议，读取的是原生模型列表，模型回复及多轮角色正常 |
| Claude | 选择 Claude 协议，Messages 流式输出正常，系统提示词生效 |

读取模型通常不消耗生成额度；发送消息可能按服务商规则计费。请使用自己的测试凭据，测试记录中勿粘贴 Key。

## 状态与界面

1. 请求长回答，确认文本逐步出现。点击停止，当前内容保留并标记停止；点击重新生成只替换最后一条助手回答。
2. 生成期间打开设置，确认不能修改正在使用的服务。切换到另一条历史对话或新建对话，旧生成任务停止，内容不会串入新对话。
3. 对话重命名、置顶、搜索、Markdown 导出。结束 App 后重新打开，历史应恢复；API Key 可继续使用。
4. 使用无效 Key、错误模型或错误路径，确认显示错误且没有把错误文本当作助手回答；修正后可以重新生成。
5. 生成期间切到后台再返回，确认状态停止且已保存。断开网络，确认展示错误并保留已显示的内容。
6. 检查 iPhone 键盘打开、长消息、长代码横向滚动、iPad 侧栏、系统深色模式和较大的辅助文字。
7. iOS 26+ 检查顶部按钮、侧栏搜索框和输入区的原生玻璃反光与滚动透视；开启“降低透明度”后检查文字可读性。iOS 17–25 检查材质回退。
8. 从左缘向右滑动或点击历史按钮打开抽屉，点击右侧露出的聊天页或向左滑动关闭；开启 VoiceOver 检查搜索、对话选择、关闭侧栏及设置关闭按钮。
9. 在设置中切换外观、字体大小、思考过程显示和自动跟随，返回聊天检查生效；重启检查偏好保留。较大辅助字体下底部左侧选择器应可以横向滚动，加号和发送保持可见，避免为选择器额外留出一行。

## 1.5 模型图标设备验收（待执行）

1. 覆盖安装 1.5.0 (10)，旧版模型继续自动显示原 Logo，Key、地址、模型参数和历史不变。模型的「图标来源」可选自动识别、OpenAI、DeepSeek、Claude、Gemini。

6. 自定义图标生成回复后更换 / 删除模型或供应商，旧回复保留原图标；清空聊天但保留使用该图片的模型，图标仍可用。确认下次启动不误删仍被模型或历史引用的图片。
7. 在 iOS 26+ 检查图标 Picker 和系统相册 / 文件弹层沿用系统样式，深色、动态字体与 VoiceOver 可用；其余二级菜单、精简推理按钮和固定弹窗布局继续按下面步骤验收。
