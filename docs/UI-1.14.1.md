# 1.14.1 灵动岛完整展开布局与可选诊断

版本：1.14.1（21）。包含 [1.14.0 的全部修改](UI-1.14.md)：搜索提供商设置内部导航、动态宽度推理按钮、弹性玻璃面板、附件复制导入与系统权限页。

## 展开状态

针对展开后只剩模型图标与名称的反馈，取消将图标/名称、计时、状态/tokens 分别放入 leading、trailing、bottom 三个展开区域的布局，统一使用一个完整宽度的 bottom 区域，并以原生 SwiftUI 两行排列：

- 第一行：22pt 供应商 Logo、14pt 模型显示名称、13pt 已用时间。
- 第二行：12pt 回复状态，以及本条回复的 tokens；估算值保留 ≈ 标识。

计时明确保留 72pt 宽度，tokens 保留 104pt；不再对没有稳定固有宽度的计时文本调用 fixedSize。左侧标题与状态使用剩余宽度，名称允许适度缩放，状态最多两行；整个展开内容至少 48pt 高，位于传感器下方。紧凑状态、最小状态和锁屏卡片继续使用已有样式；计时仍由系统 timer 文本更新。

这避免展开内容跨多个区域协商尺寸，但当前没有设备运行条件，不能确认原症状的确切系统布局原因，也未将编译检查当作原症状的复现/验收。安装后可在“后台生成”中运行无需 API 的“测试灵动岛与锁屏显示”，核对图标、名称、计时、状态与 123 tokens。

## 实时活动诊断

“后台生成 → 实时活动诊断”始终显示，加入苹果原生 Switch：“记录实时活动诊断”。开关默认关闭并保存在本机，只有开启后才新增应用诊断事件：既包括页面可导出的记录，也包括本 App 写入 OSLog 的实时活动事件。

关闭记录不会停止实时活动、清除旧记录或隐藏当前运行状态；当前状态仍会更新。历史记录最多保留最近 16 条。“导出诊断记录”下方新增“删除诊断记录”，两者在 iOS 26+ 均使用苹果原生 `.glass` 按钮。没有记录时禁用导出和删除。

删除立即清空内存数组及 UserDefaults 中的本地记录，不再为删除操作新增一条诊断事件。若开关仍开启，后续新事件仍可记录。此操作管理 App 自己的可导出历史，不尝试删除 iOS 维护的系统统一日志。
