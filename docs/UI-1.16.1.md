# 1.16.1（27）：回答分享按钮与图片导出修复

## 分享按钮尺寸

回答底部的分享图标与复制图标共用网页内的 `.message-action` 样式：40 × 40 点点击区域、10 点内边距、20 × 20 点 SVG 画布。原来的额外 SF Symbol 图标移除，透明 `UIButton` 覆盖在原图标位置，只负责原生 `UIMenu` 与辅助功能。这样两者的可见大小、线宽、颜色和点击区域保持一致，仍然使用系统原生保存菜单。

## 图片准备卡住

旧版单独建立离屏 `WKWebView` 导出完整对话，调用的 `updateTranscript` 和导出函数各自等待一次 `requestAnimationFrame`。离屏 WebKit 可以暂停显示刷新回调；页面已经载入，但这两个 Promise 可能永远不完成。旧版的超时只保护初始页面载入，无法释放此后的“正在准备保存”状态。

桌面回归在实际导出 JavaScript 入口暂停动画帧，修复前运行 `node test-transcript.mjs` 得到 `Export stayed in preparation when animation frames were suspended`。修复后相同场景可在 1.5 秒测试预算内返回非零文档高度。

- 图片导出进入独立模式，直接使用 DOM 布局测量，不等待动画帧；聊天页面原有的滚动确认流程保留。
- 导出样式在渲染前启用，懒加载图片主动开始加载；字体与图片等待共用 8 秒上限，避免单项资源让导出一直悬停。
- 原生载入、排版、PDF 回调分别设置 20、45、30 秒上限；网页进程中断、超时或取消均释放相应等待，迟到回调不会二次完成。
- 准备阶段显示载入、排版、生成图片和保存相册的进度文字，并提供取消入口。栅格化仍在后台任务执行，失败或取消清理临时文件。
- 保存内容仍为当前完整对话，采用原有 2400 万像素、最大边长 32000 像素的 PNG 预算；过长对话缩小，不滚动或裁掉当前聊天记录。

## 验证范围

8 项富文本与 21 项对话桌面渲染检查通过，其中包括原生分享锚点与复制按钮相同的几何尺寸，以及暂停动画帧时导出准备仍能完成的回归。96 项核心 XCTest、10 项分享队列回归和 iOS arm64 Release 构建结果记录在 `local-validation.json`。

Windows + WSL 环境未连接 iPhone。上述回归验证了 JavaScript 挂起条件及修复，不能替代 iOS 27.2 上的原生菜单、WebKit PDF、相册保存、按钮视觉效果或取消交互验收。
