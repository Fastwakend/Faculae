# 1.4.0 (8)：供应商下管理多个模型

一个供应商现在管理地址、协议和一份 Key，下面可添加多个模型。无需为同一个接口重复创建供应商。预置 DeepSeek、OpenAI、Gemini 和 Claude 配置均可添加多个模型。

## 使用

1. 进入「设置 → API 与模型」，选择供应商。
2. 点击「手动添加模型」，填写 API 模型 ID；或点击「读取模型 / 测试连接」，再进入「从列表添加」，搜索并多选模型。
3. 点开模型可编辑 ID、系统提示词、最大输出和 Temperature，也可选为供应商默认项。左滑可移除，至少保留一个模型。
4. 在供应商页面点右上角勾号保存，地址、Key 和模型草稿一并生效。取消供应商编辑会放弃本次草稿。
5. 回到聊天页，顶部菜单和底部模型标签都按供应商分组列出模型。菜单勾选项为当前模型，切换后成为该供应商下次使用的选中项。

推理等级跟随模型分别保存，仍按模型系列显示原有四组档位。生成请求捕获当前模型及其参数，生成期间禁止切换或修改供应商。输入区标签显示当前模型 ID，长名称截断；详细 ID 可在菜单和模型设置中查看。

新增页面沿用 SettingsScaffold、原生 Form / List、原生提示框及玻璃导航按钮。Temperature 继续使用官方 Slider / Switch；没有为模型多选自绘开关。原有推理 popover 锚点宽度、暂停底部横向滚动和移除底部说明小字的布局均保留。

## 数据

- `APIProfile.id` 仍表示供应商，Keychain 继续使用此 UUID，因此多个模型共用一份凭据。
- `APIModel` 有稳定 UUID，单独保存模型 ID、系统提示词、输出上限、Temperature 和推理等级。
- v1 单模型配置自动转换为一个模型条目，保留原供应商 UUID、地址与全部参数；首次保存升级为 v2。
- 新聊天保存 `Conversation.modelID`，选择历史和重启时恢复模型。旧聊天无此字段时按最后一条助手回复的模型名匹配；找不到时保留现有选择。
- 模型改名保留 UUID；删除当前模型回退到首个。空 ID、同供应商重复 ID 及删除最后一个模型会被拒绝，Gemini 的 `models/` 前缀参与规范化去重。
- 保存供应商前验证全部模型，避免未激活的无效模型混入配置。损坏的空模型集合不会静默重置覆盖原存档。

## 验证

52 个核心 XCTest 包含 10 个多模型测试，覆盖旧 JSON 迁移、共享地址和 Key 的请求、独立参数、持久化、去重、删除回退、稳定 UUID、全部模型验证以及新旧历史模型恢复。Windows / WSL 下可编译 arm64 Release IPA，实际构建与产物校验记录见 [local-validation.json](local-validation.json)。
