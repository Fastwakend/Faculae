# 1.6.0 (11)：模型显示名称与菜单对齐

每个模型有两个名称：

- 模型名称：实际 API 模型 ID，继续用于请求路由、模型匹配和推理档位识别。
- 显示名称：界面上的自定义名字，可在「设置 → API 与模型 → 供应商 → 模型」修改。留空或仅填空白时使用模型名称。

显示名称用于聊天输入栏、模型二级菜单、供应商摘要、模型列表和新回复头像旁的文字。模型列表在自定义显示名称下方保留真实 ID，方便区分。名称更改只在保存模型、再保存供应商后生效；取消保持正式配置。显示名称无需唯一，实际 API 模型 ID 仍按原规则去重。

聊天输入栏用对应供应商 / 模型 Logo 替换原地球图标，沿用每模型四家内置 Logo 和自定义图片设置，默认自动识别。标签保留固定宽度和单行截断，避免长名称挤占推理与发送。推理按钮固定锚点布局不变。

## 原生菜单文字对齐

此前已选项为带勾号的 Label，未选项仅有 Text，系统为两类项目分配了不同的图标空间。现在两级菜单使用相同的 MenuSelectionLabel：已选项显示系统勾号，未选项提供透明位图，让系统保留同一列图标位置。没有使用可见空格缩进或另画弹层，菜单仍由嵌套原生 Menu 提供 iOS 26+ Liquid Glass。

## 保存与请求

APIModel 新增可选 `displayName`，读取旧存档时自动为空，`displayTitle` 回退真实 ID。模型 UUID、供应商 UUID、Keychain 和存档版本均不变。`updateModel` 仅修剪显示名称首尾空白，不更改实际 ID。

回复新增可选 `modelDisplayName`，记录生成时的显示名称。后续改名不重写此前回复，历史选择仍按模型 UUID / API ID 恢复。请求构建继续使用 `APIProfile.model` 和原有消息内容，不发送显示名称。

## 验证

61 项核心 XCTest 全部通过，其中 5 项新增测试覆盖旧字段缺失、独立名称的规范化与持久化、三种协议请求与改名前一致、历史回复名称保存，以及显示名称与模型 ID 去重的分离。已完成 Swift / 工程静态检查、arm64 Release 编译和 IPA 资源、原生控件及链接 SDK 检查，记录见 [local-validation.json](local-validation.json)。

本轮未连接真机或运行模拟器，原生菜单的实际对齐、Logo 尺寸、文字截断和 VoiceOver 仍需按 [DEVICE-TESTING.md](DEVICE-TESTING.md) 验收。
