# 1.8 聊天交互、滚动与原生边缘模糊

## 修复与行为

- 模型和推理按钮改为苹果 GlassButtonStyle。模型按钮使用原生玻璃着色保持白字可读；iOS 26.1+ 使用 GlassButtonStyle 的 Glass 参数，26.0 使用原生 glassProminent，旧系统回退为 bordered。
- 两个按钮处于同一紧凑 HStack，间距 8 点，推理按钮随模型名称自然增长向右移动；超长名称可以连同推理按钮横向滚动。附件与发送在右侧保留触控空间。
- 推理使用系统 Popover，保持 316 点宽度，紧凑屏幕也保留 Popover。内容只使用系统提供的背景，不再与输入框共用自绘浮层或 glassEffectID。原生 Slider、档位和稳定标题占位保留。弹层展示时锁定按钮所在横向滚动区。
- 移除始终存在的全屏 GeometryReader 锚点层，避免透明层拦截顶部按钮。两个顶部按钮增加明确圆形触控区域，仍分别调用历史抽屉和新对话动作。
- 聊天画布向上扩展设备实际 top safe area；父层固定可用尺寸，不再裁掉状态栏背景。标题容器按相同 top safe area 向下留空，按钮和文字位于灵动岛下方，键盘和底部安全区保持由系统布局。
- iOS 26+ 直接使用 UIScrollView.topEdgeEffect.style = .soft，并用 UIScrollEdgeElementContainerInteraction 把实际标题容器与滚动视图关联。系统负责渐变高斯模糊与保护背景。本版未使用私有 CAFilter / variableBlur 或普通渐变色冒充系统效果。iOS 17–25 回退为系统材质。

## 滚动回归原因与处理

1.7 的 LazyVStack 为每条助手消息创建一个 WKWebView。每个实例独立加载约 5.5 MB 脚本，消息离屏回来时又触发实例、字体和布局准备。每条正文的高度还通过 PreferenceKey 汇总到父视图，随后调用 scrollTo，形成重复测量和更新。

1.8 改为每个聊天视图一个长期复用的 WKWebView，直接由其原生 UIScrollView 滚动。文章、推理和代码节点按消息 UUID 保留，只有新增或变化的消息通过结构化参数增量更新；不再把每条消息的高度传回 SwiftUI。用户拖动或惯性滚动时不会抢滚动位置，只有初次打开或用户选择跟随时才滚到底部。

图表库单独打包且按需加载；普通聊天不解析 Mermaid。思考正文等用户展开时才排版。附件缩略图在后台解码，并按固定尺寸显示。每次流式输出采用 100 ms 节流，持续有 token 时也能更新，避免不断重启 debounce 定时器。

## 设备验收

当前主机是 Windows / WSL，没有 iOS 模拟器或连接的 iPhone。安装后需要检查：

- 连续点左上角打开侧栏，选历史后关闭；右上角从已有聊天回到空白新会话，并验证正在生成时会停止旧任务。
- 不同长短显示名称下推理按钮位置随名称变化；拖动 Slider 时弹层不融合、不左右跳动，外部点击收起。
- iPhone 灵动岛、刘海、横屏及 iPad 分屏下标题和按钮不进入遮挡区，聊天内容背景延伸至状态栏，系统模糊随滚动变化。
- 长对话快速上下甩动、流式输出、键盘展开 / 收起、自动跟随关闭、表格横向滚动、代码复制、原生分享、模型图标和附件缩略图。
- VoiceOver 顺序和推理内容展开、系统减少动态效果设置。

模型、配置、Keychain 身份及历史 JSON 格式均不变；无需重新输入 Key。
