# 2.2.0（31）：设置点按导航与列表排序

## 设置点按导航

上版为触觉反馈添加了导航行上的 `TapGesture`：设置首页的 `SettingsRow` 以及供应商、模型、余额配置链接使用的 `hapticListTap`。这些额外手势可能与 SwiftUI 的系统点击识别竞争，与用户反馈的“必须长按才能进入”相符。

本版移除上述手势和 helper，恢复由原生 `NavigationLink` / `Button` 独立处理点按。设置行保留完整矩形点击区域，文字、空白与右侧箭头均属于同一入口。触觉反馈改为由 `SettingsScaffold.onAppear` 观察页面进入，不在导航标签上注册手势；仍受全局与列表项触觉设置控制。

这是基于上版变更与调用位置进行的修复。当前主机无法运行 SwiftUI / iOS 手势系统，未复现真机上的长按故障，也未将静态检查称为点按回归通过。

## 供应商、模型、搜索提供商排序

三个列表的标题右侧均增加原生液态玻璃「排序／完成」按钮。点击「排序」进入系统编辑模式，通过行右侧把手拖动排序，点击「完成」退出。采用 SwiftUI `EditMode`、`ForEach.onMove` 和 `moveDisabled`；普通浏览模式保留点按编辑。

| 列表 | 位置 | 保存与同步 |
| --- | --- | --- |
| 供应商 | 设置 → API 与模型 → 供应商 | 每次移动直接保存；聊天模型菜单的供应商顺序同步 |
| 模型 | 编辑供应商 → 模型 | 与其他模型设置一起在右上角勾号保存；聊天对应供应商的二级菜单同步 |
| 搜索提供商 | 设置 → API 与模型 → 搜索提供商 | 每次移动直接保存；聊天联网搜索菜单顺序同步 |

供应商与搜索提供商共用页面时，每次只编辑一个分类的顺序。排序时关闭该页面的添加入口与上下文删除入口；模型列表排序时不显示左滑删除。正在生成回复时不允许改动列表配置。

排序直接变更现有数组，聊天菜单也直接按这些数组生成，不增加第二份排序状态，不重新按名称排序。原有 v3 JSON 格式已保存数组顺序，重启后可还原，无需迁移。供应商、搜索服务、模型的 UUID、Keychain 对应身份、模型参数和默认选择均保留。模型编辑为草稿，取消编辑会放弃未保存的顺序。

共享的 `ListOrdering` 处理 SwiftUI 原数组偏移语义，支持向上、向下、移动到末尾及多项移动；无效或未变化的移动不修改数据。

## 验证

- 121 项 Linux 核心 XCTest、10 项分享导入文件测试通过；新增 6 项排序测试覆盖首尾/多项移动、无效偏移、所有单项移动插入位置、供应商与搜索配置编码还原，以及模型参数、选择和草稿独立性。
- 88 个 Swift 文件通过静态语法与项目引用检查；48 个 App 源文件纳入 Xcode target。
- 主 App 与两个扩展完成 iOS arm64 Release 编译及 IPA 打包，主 App 无编译警告。扩展保留 Linux lld 对 iOS 平台交叉链接的已知警告。
- 本版未更改消息渲染器和 WebP；沿用 2.1.0 的 34 项桌面渲染结果、2.0.0 的两项 Linux 编解码结果，没有重复记为本版执行。
- 打包时核对编译副本与交付源码，校验主应用和两个扩展的版本、ZIP CRC 和 SHA-256。

未连接 iPhone，也无法在当前 Windows/WSL 主机运行 Apple iOS Simulator。原生点按、拖动把手、编辑模式动画、菜单展示、重启后的界面恢复与实际触觉仍需真机验证。当前未签名 IPA 安装时需一并签名主应用和两个扩展。
