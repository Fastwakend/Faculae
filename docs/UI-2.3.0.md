# Seek API 2.3.0（32）：持续后台任务与实验性保活

在「设置 → 应用 → 后台生成」打开后台生成后，前台发送消息会向 iOS 26 及以上系统申请 `BGContinuedProcessingTask`。iOS 27 使用新的异步提交接口以获取完整的失败原因。较旧系统继续使用原来的短期后台时间。

## 官方持续后台任务

- 每条回复使用独立任务标识，启动前注册一次，再在用户前台发送时提交。请求采用 `.fail` 策略；资源不足时立即失败，避免排队后再次发起收费请求。
- 请求提交和任务真正启动分别显示状态；只有系统调用启动处理器后，才算获得持续运行机会。设置可查看运行与等待数量。
- 已存在的流式请求继续运行，不为后台任务重复调用模型接口。真实收到的文本和思考内容字节数用于更新 `Progress` 与系统任务副标题；总量未知时使用不确定进度，不用计时器伪造百分比。生图等待期间同样不虚构进度。
- 完成时报告成功，失败、停止或取消时报告失败并释放任务。晚到的提交、启动、结束回调不能重新启动已结束的回复，也不能影响其他会话。
- 官方任务的系统界面由 iOS 提供，独立于 App 原有的 ActivityKit 锁屏/灵动岛内容，可能出现额外的任务进度入口。用户通过系统界面取消时会停止对应回复。
- 短期 `beginBackgroundTask` 到期后，不再一律取消所有回复；仅中止既没有运行中的持续任务，也没有其他有效执行服务的回复。后台恢复机会也使用相同协调逻辑。

## 实验性功能

新增「实验性功能」分类，两个开关默认关闭，均复用原生 `Toggle` / `Switch`，iOS 26+ 由系统提供液态玻璃外观。

| 开关 | 行为 | 结束与中断 |
| --- | --- | --- |
| 后台定位保活 | 开启时申请「使用期间」定位权限；有真实生成任务时，在前台启动 `CLBackgroundActivitySession` 和持续定位，允许后台更新、关闭自动暂停、显示系统定位指示。可自行申请「始终允许」或跳转设置。 | 最后一个任务结束、关开关或关闭后台生成后停止定位并失效化会话；权限撤销、会话诊断失败会更新实际状态。 |
| 静音音频保活 | 有真实生成任务时，以 `.playback` + `.mixWithOthers` 激活音频会话并循环播放全零 PCM WAV。不会请求麦克风权限。 | 最后一个任务结束、关开关或关闭后台生成后停止播放并释放会话；处理来电中断、恢复许可、媒体服务丢失/重置、播放失败与旧播放器回调。 |

两项均依赖后台生成总开关；多个会话生成时共享服务，某一个任务完成不会停止其他回复的服务。退出当前聊天、查看设置或灵动岛显示测试不计为新的生成任务。没有任务时不会启动定位或静音播放，重启 App 不自动恢复上一次实验性服务。

位置数据不会保存、记录或上传。定位状态与授权显示在后台生成页面，「关于 → 系统权限」也加入定位入口。主 App 两套构建 plist 同步声明 `audio`、`location`、持续任务标识前缀和两项定位权限说明。

这些服务会增加耗电，并可能显示系统定位/音频状态；它们不能保证无限运行。资源不足、等待响应无进度、系统中断、断网和手动划掉 App 仍可能终止回复。系统持续任务的到期处理器同时用于用户取消，收到该回调会结束对应回复，不借实验性服务绕过取消。进程结束后的 SSE 仍不能无缝接回，恢复功能不会自动重新请求和计费。

## 验证范围

- 129 项核心 XCTest 通过，包括新增 8 项任务生命周期测试：提交与授权分离、并发释放、晚到回调、旧请求隔离、单任务到期、共享时间协调、总开关和重复注册防护。
- 10 项系统分享导入文件测试通过。
- Windows/WSL + Apple iOS SDK 27.2 完成主 App 和两个扩展的 Release 交叉编译。IPA 检查包含后台模式、权限、持续任务类与定位/音频 API 链接；这些是编译与静态产物检查。
- 渲染器和 WebP 未改动，沿用 2.1.0 的 34 项桌面渲染结果及 2.0.0 的 2 项编解码结果。
- 本机无 iOS 运行环境；尚未验证系统持续任务是否获准、真机授权、定位指示、音频会话、实际后台时长和电量影响。编译和核心测试不能替代这些系统行为验收。

## iOS 27.2 安装后验收（待执行）

1. 主 App 与两个扩展一起签名安装，覆盖升级确认配置、Key 与历史保留。先关闭两项实验性功能，前台发送较长回复，查看官方任务状态由请求中变为运行中，再返回桌面或锁屏；检查内容继续接收及最终保存。
2. 发送两条不同会话的回复，在官方系统任务界面取消其中一条；仅对应会话停止，另一条继续。网络失败、停止与正常结束后，运行数量应归零。
3. 开启定位但不发送：只应申请授权，不持续定位。发送后查看系统定位指示；两条同时生成时完成一条，定位应继续，最后一条完成后停止。拒绝权限、只允许一次、允许使用期间、始终允许、系统关闭定位分别检查状态及重开设置流程。
4. 开启静音音频但不发送：不应开始播放。生成期间切后台、锁屏，并与其他音乐、来电、蓝牙音频切换组合检查；结束后播放会话释放，系统中断时状态应更新。
5. 生成中分别关单个实验性开关、关闭后台生成总开关、手动停止、断网失败、快速结束再生成；确认没有残留定位/音频，旧回调不停止新播放。退出 App 再打开，不应在没有任务时恢复服务。
6. 长时间等待首个响应及较慢生图分别测试。记录后台存活时长和系统持续任务状态，不能仅凭灵动岛存在判断 App 仍可接收网络。
